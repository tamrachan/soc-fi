# Where to find each judging criterion

| Criterion | What to look at |
|---|---|
| **Technical execution** (25%) | A real end-to-end payout: a claim in the app, the agent's verdict, clear-signed on an emulated Nano S Plus, USDC on Base Sepolia ([backend/README.md § What has been verified](../backend/README.md#what-has-been-verified)). Signing: [`backend/src/ledger.ts`](../backend/src/ledger.ts), [`backend/src/payout.ts`](../backend/src/payout.ts). Key Ring: [`backend/scripts/keyring.cjs`](../backend/scripts/keyring.cjs), [`backend/src/secrets.ts`](../backend/src/secrets.ts). The checks: [`frontend/src/domain/rules.js`](../frontend/src/domain/rules.js) and [`backend/src/agent.ts`](../backend/src/agent.ts). |
| **Usefulness and relevance for Ledger** (20%) | The Ledger is the only thing that can move money, and no server holds a wallet key. Key Ring also seals the agent's own API key. See [the boundary](../README.md#how-it-works) and the [security model](ARCHITECTURE.md#security-model). |
| **Innovation / originality** (20%) | The agent decides each claim on its own but cannot pay. The [attack demo](DEMO.md#the-attack-demo) turns the software safeguards off on purpose; the recipient check and the Ledger screen still catch the wrong wallet. |
| **User experience** (15%) | Open the [live demo](https://tamrachan.github.io/ledger-hackathon/) on a phone: scan a receipt, correct a field, submit. Free on-device OCR: [`frontend/src/domain/reader/`](../frontend/src/domain/reader/). |
| **New use cases for Ledger** (10%) | The pattern (an agent proposes, a person signs on hardware) and where else it applies: slides 9 and 15 of the [pitch deck](../pitch/SocFi-pitch.pdf). |
| **Clarity, presentation and documentation** (10%) | The one-page [README](../README.md), [SUBMISSION.md](SUBMISSION.md) (developer feedback for Ledger), the [backend README](../backend/README.md) (API, gotchas), [HANDOVER.md](HANDOVER.md) (schemas, status machine, API contract) and the [deck](../pitch/SocFi-pitch.pdf). |
